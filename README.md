# 论文格式一键排版

帮同学改论文格式时发现，真正耗时的不是「改」，而是**判断哪一条不合格**：
字号差半号、行距差 0.25、首行没缩进，肉眼看不出来，只能一条条对着要求量。

后来换了个做法：把「合格」的标准写成配置文件，让程序去比对，人只看结果。

> **默认格式已经设好，打开就能用**：A4、正文宋体小四单倍行距、一级标题小三黑体、
> 页码小五号居中。这套取值参考自高职院校的毕业论文规范，逐项出处见
> [格式规范.md](格式规范.md)。换学校只需改 `rules.yaml`，不用动代码。
>
> **不想装 Python？** 到 [Releases](../../releases) 下载 `ThesisFormatter.exe`，双击就能用。
> 首次下载和运行会被系统拦两下（没买签名证书），点「仍然保留」和「仍要运行」即可。
> 详细步骤见 [使用说明.md](使用说明.md)。

## 现在能做什么

一条命令，按规则把整篇论文的格式刷一遍：

```bash
python format_docx.py 我的论文.docx
```

输出 `我的论文-已排版.docx`，原文件不动。

覆盖范围：

| 类别 | 项目 |
|---|---|
| 页面 | A4 纸张、上下左右页边距、页脚页码 |
| 正文 | 中文字体、英文字体、字号、行距、段前段后、首行缩进、对齐方式 |
| 标题 | 一级 / 二级 / 三级，各自独立配置字体字号加粗与间距 |
| 其他 | 图题表题（Caption 样式）、参考文献（Bibliography 样式） |
| **结构重建** | 自动识别并修复「AI 生成 / 网页复制 / 系统导出」的文档（见下） |
| **代码块** | 自动识别 1×1 表格形式的代码，改用 Consolas 等宽、无缩进、小一号字 |

### 能处理三类文档

| 文档来源 | 典型问题 | 工具怎么处理 |
|---|---|---|
| 正常用 Word 写的 | 标题套了样式，只是格式不对 | 直接改样式表 |
| **AI 生成后粘进 Word** | 格式全是手动的，还带着 `#`、`**`、`---`、`\| --- \|` | 先洗掉 Markdown 残留、把 `#` 转成真标题、清掉手动格式，再套样式 |
| **业务系统导出** | styles.xml 是空的，段落引用了不存在的样式 | 先补样式表、按字号推断标题层级，再套样式 |

判断是自动的：检测到「直接格式占比超过一半」或「样式表缺失」就重建结构，
正常文档不动。想强制控制，改 `rules.yaml` 里的 `normalize: auto / on / off`。

## 怎么用

**1. 装依赖**

```bash
pip install python-docx pyyaml
```

**2. 检查 `rules.yaml`（通常不用改）**

默认值已经是一套完整规范。如果指导教师另有规定，改这个文件即可；
每一项都有中文注释，字号支持「小四」「三号」这种中文号数，也支持 12、16 这种磅值。

**3. 跑**

```bash
python format_docx.py 我的论文.docx
```

**4. 用 Word 打开输出文件核对**

## 自定义格式

界面上有一栏「自定义格式」，按学校文件上的说法写就行，一行一条：

```text
正文：宋体 小四，单倍行距，首行缩进2字符
一级标题：黑体 小三
二级标题：黑体 四号
三级标题：黑体 小四
页边距：上2.54 下2.54 左3.17 右3.17
```

### 能写什么

| 项 | 可以写 |
|---|---|
| 设置项 | 正文 / 一级标题 / 二级标题 / 三级标题 / 题注 / 大标题 / 页边距 |
| 字体 | 宋体、仿宋、仿宋_GB2312、黑体、楷体、微软雅黑、等线、Times New Roman…… |
| 字号 | 初号～小六，也可以写 `12pt` 或 `12磅` |
| 行距 | `1.5倍`、`单倍`、`固定值22磅` |
| 缩进 | `首行缩进2字符`、`不缩进` |
| 对齐 | 居中 / 左对齐 / 右对齐 / 两端对齐 |

**顺序随便，也不要求写全。** 甚至能直接写「正文采用宋体小四号，行距1.5倍」这种整句。

### 生效范围

1. **只覆盖你写的那几项。** 只写「正文」，标题格式不受影响。
2. **只对本次运行生效。** 关掉程序就恢复默认。
3. 点「保存为默认」后，下次打开自动读取，**优先级高于 `rules.yaml`**。

### 保存方式

| 操作 | 结果 |
|---|---|
| 点「应用」 | 立即生效，只作用于当前这次 |
| 点「保存为默认」 | 写入 exe 同目录的 `我的格式.txt`，下次启动自动加载并回填到输入框 |
| 点「清空」 | 回到 `rules.yaml` 或内置默认 |
| 删掉 `我的格式.txt` | 同样回到默认 |

**为什么单独存一个文件、不回写 `rules.yaml`：** `rules.yaml` 里全是注释，程序回写会把注释冲掉。
单独存你输入的那几行，两份互不干扰。

### 写错了会怎样

点「应用」时立刻告诉你第几行、哪里看不懂：

```text
第 2 行：不认识的设置项「脚注」。可写：正文、一级标题、二级标题、三级标题、题注、大标题、页边距
第 3 行：这部分没看懂：「稍微小一点」
```

**有错时不会静默退回默认规则**——否则你以为改了、实际没改，更难发现。

## 前提：你的标题得用「样式」

工具改的是 Word 的**样式表**，所以标题必须是用 Word 的「标题 1 / 标题 2」标出来的，
不能用「选中文字 → 加粗 → 字号调大」手动做。

**怎么检查：** 跑一遍，看输出里的「一级标题段落」是不是 0。如果是 0，说明没识别到。

**怎么改：** 在 Word 里选中标题 → 开始 → 样式 → 标题 1（快捷键 `Ctrl+Alt+1`）。
二级是 `Ctrl+Alt+2`，三级是 `Ctrl+Alt+3`。

## 已知限制与取舍

这一节不是免责声明。下面每一条都是设计时做过的判断，写清原因和代价。

### ① 会重建文档结构，但只做一轮

**原因：** 逐段改格式的话，用户后来在 Word 里新加一段，格式又会变回去。
改样式表才能「一处改、全文生效」。但样式表压不住「直接格式」，
所以遇到这类文档必须先重建结构。

**做法：** 重建时做这几件事——

1. Markdown 标记转成 Word 结构（`#` → 真标题、`**` → 加粗、`---` 删除）
2. 按字号推断标题层级；字号明显偏大的单独识别为文档大标题（Title），不占一级
3. 清除段落和文字上的手动格式，改由样式统一控制
4. 删掉多余空段落（保留含图片、分页符的）
5. 表格：表头跨页重复、单元格取消继承正文的缩进、代码块（1×1 表格）改用等宽字体
6. 删除 AI 工具加在文末的署名（`|（注：文档部分内容可能由 AI 生成)`）

**代价：** 会改写文档结构，所以工具**永远另存新文件，原件不动**。

**取舍：** 重建有误判风险——比如把某个加粗的强调句当成标题。
所以判据卡得比较严：必须是字号比正文大 1pt 以上，
或者「加粗 + 短 + 不以标点收尾 + 带编号前缀」。
即便误判，用户在 Word 里改回来，也比手动重排整篇省事。

**做不到的：** 判断标题的语义层级。工具只能按字号大小排序，
「1.1 研究背景」如果字号比「第一章 绪论」还大，就会排错。
这类问题要人工看一眼。

### ② 不解析学校发的格式要求文档，只读 YAML

**原因：** 格式要求是人写的自然语言，「正文小四、行距 1.5 倍、段前 0 段后 0」这句话，程序读不懂；
让模型去抽取一定会出错，而格式错了比不排版更糟。

**代价：** 用户要手填一次配置，大约 5 分钟。

**取舍：** 手填 5 分钟，比「自动解析错了再人工逐条找错」可靠。
后续版本会加模型抽取，但「人工确认」这一步不会省。

### ③ 页脚已有内容时跳过页码

**原因：** 学校模板的页脚经常有「XX 学院毕业论文」这类字样，直接覆盖会丢内容。

**代价：** 这类文档需要用户自己去 Word 里加页码。

**取舍：** 宁可少做一步，也不做破坏性操作。工具出错最多是不生效，不能是「把别人的东西弄没了」。

### ④ 参考文献只认 `Bibliography` 样式

**原因：** 参考文献格式差异极大（GB/T 7714、APA、IEEE），硬编码一种会误导用户。

**代价：** 多数中文论文的参考文献是手动排的，用不上这一项。

**取舍：** 先不做。等真的有人需要，再按那种格式单独支持，而不是做一个「大概对」的版本。

### ⑤ 表格内部、图片尺寸不动

**原因：** 表格的规则比段落复杂得多——跨页重复表头、单元格边距、行高最小值、文字垂直居中，
每一条都能单独出问题。做一半比不做更糟。

**代价：** 表格多的论文仍需人工检查。

**取舍：** 明确写进限制，让人知道边界在哪，比让人自己去试出来要好。

## 为什么做这个

作者是新能源汽车技术专业在读，方向是车载 AI 的测试与评测。

做这个工具的起点很具体：帮同学改论文格式，发现真正花时间的不是「改」，
而是「判断哪一条不合格」——这跟测试里的手工点检是同一个问题：
**标准在心里，全靠人逐条比，人和人之间还不一致。**

所以换了个做法：把标准搬到文件里，让程序去比。

三个环节，对应测试工作里的三件事：

| 这个项目 | 测试里的对应物 |
|---|---|
| `rules.yaml` 定义「什么算合格」 | 预期结果 / 断言 |
| `format_docx.py` 逐项套用并核对 | 执行用例 |
| 检测不到标题样式时给出具体指引 | 失败归因，而不只是报错 |

谈不上复杂。但把「规则从人脑子里搬到配置文件里」这件事完整走了一遍——
包括想清楚哪些不做、为什么不做的理由。
